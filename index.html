MISSION STATEMENT

MISSION_DIRECTIVE.log

$ cat MISSION_DIRECTIVE.log

The Galactica Network Security Team is dedicated to protecting the integrity of Colonial Fleet computer systems through network security practices, technical procedures, and strong system design. Our manual provides guidance for personnel responsible for maintaining, operating, or interacting with digital infrastructure aboard fleet vessels.

🎯

PRIMARY AUDIENCE

Fleet technicians, communications officers, and junior system administrators who manage shipboard networks.

📋

SECONDARY AUDIENCE

Command personnel and general crew members who must follow security protocols when interacting with digital systems.

🔒

SCOPE

Prevention and detection of network vulnerabilities — improper configuration, insecure channels, compromised credentials, and unauthorized access.

Through clear documentation and standardized practices, the Galactica Network Security Team aims to ensure that all personnel interacting with digital systems understand their role in maintaining network security. By prioritizing consistent and reliable responses to network crisis, this manual supports the fleet's broader mission of survival and strategic coordination.

03

CODE OF CONDUCT

Members of the Galactica Network Security Team are responsible for the protection of fleet systems. All personnel interacting with digital systems are expected to uphold the following principles:

01

OPERATION INTEGRITY

Personnel must prioritize the stability and functionality of fleet systems before convenience. All actions taken on a system should be aligned with established procedures.

02

SECURITY ACCOUNTABILITY

Every user is responsible for maintaining the security of our systems. Credentials must not be shared, and any irregularities must be reported and handled immediately.

03

CONTROLLED ACCESS

Access to systems must be limited to authorized personnel only. Users must follow all access protocols to prevent exposure or misuse of sensitive information.

04

CONTAINMENT OVER RISK

In the event of a suspected breach, personnel must prioritize isolation and containment over continued operation. Preserving system integrity is critical to fleet survival.

05

THREAT AWARENESS

Personnel must always remain alert to potential vulnerabilities. Systems should be routinely monitored, updated, and evaluated to identify risks before they become threats.

06

COLLECTIVE RESPONSIBILITY

Network security is not limited to technical staff. Command personnel, communications officers, and crew members all play a role in maintaining secure operations.

⚠

Failure to follow these principles risks system failure and the survival of the fleet as a whole.

04

INTRODUCTION // KEY CONCEPTS

The following definitions establish a shared operational vocabulary for all personnel interacting with fleet systems. Familiarity with these terms is required before engaging with any security protocol.

NET-SEG Network Segmentation

Dividing a network into sections so that intrusions in one area cannot spread to other systems. Critical for containing potential Cylon intrusion vectors.

SEC-ACC Secure Access

The process of verifying identity before allowing someone to use a system, typically through passwords, access codes, or clearance levels.

COMP-SYS Compromised System

Any device that has been accessed, altered, or controlled by an unauthorized user. Immediate isolation is required upon detection.

INC-RES Incident Response

The actions taken after a security issue is detected, including isolating vulnerable systems, reporting the issue, and restoring normal operations.

FSI Fail-Safe Isolation

A system feature that automatically shuts down critical components when a threat is detected to prevent further damage.

COM-DIS Communication Discipline

The practice of following strict rules when sending or receiving information to prevent interception or exploitation of fleet communications.

05

THREAT IDENTIFICATION

All personnel must be capable of recognizing the signs of a network compromise. The following categories represent the primary threat vectors identified by the Galactica Network Security Team.

CRITICAL

Unauthorized System Access

Attempts by unverified personnel or external agents to access restricted systems. Indicators include failed login sequences, unexpected access at unusual hours, and unfamiliar device signatures on the network.

Failed logins Unknown devices Off-hours access
HIGH

Compromised Credentials

Personnel credentials that have been stolen, shared, or otherwise exposed. These allow an attacker to move through the system as an authorized user, making detection significantly more difficult.

Shared passwords Unusual user behavior Duplicate sessions
HIGH

Insecure Communication Channels

Unencrypted or improperly secured communication links that expose data in transit. Fleet communications that bypass standard encryption protocols are considered active vulnerabilities.

Unencrypted traffic Rogue relay signals Protocol bypasses
MODERATE

Improper System Configuration

Systems configured with excessive permissions, unnecessary open ports, or outdated software create exploitable entry points. These vulnerabilities are often present before any active attack begins.

Open ports Excess permissions Outdated software
MODERATE

Lateral Network Spread

An attacker who gains access to one system may attempt to move laterally across an unsegmented network. Without proper isolation, a single compromised node can lead to fleet-wide system failure.

Cross-segment traffic Unusual data transfers Cascading failures
MONITOR

Social Engineering

Manipulation of personnel to disclose credentials or bypass security procedures. Crew members may be deceived through false authority, urgency, or impersonation of trusted personnel.

Unusual requests Identity unverified Pressure to bypass protocol
06

CORE PROCEDURE

RESPONDING TO A SUSPECTED NETWORK COMPROMISE

PURPOSE

Outlines the required steps for identifying, containing, and reporting a suspected network compromise. Prompt action is critical to preventing the spread of system-wide threats.

AUDIENCE

Communications officers, technical personnel, and any crew member authorized to access fleet systems.

WHEN TO USE

Use the steps below if you observe unusual system behavior, unexpected system commands, or loss of control over a device.

STEP 01

Confirm Suspicious Activity

Verify that the issue is not caused by standard system operations or user error. Do not attempt to troubleshoot beyond basic confirmation.

STEP 02

Isolate the System

Immediately disconnect the affected device from the network. Disable wireless or wired connections. Do not power off the system unless instructed.

STEP 03

Cease All Unnecessary Actions

Stop all activity on the affected system to avoid further compromise or data corruption.

STEP 04

Report the Incident

Notify your chain of command and the Network Security Team immediately. Provide: location of the system, a description of the issue, and the time the issue was first observed.

STEP 05

Secure Access Credentials

Do not reuse or share any credentials associated with the affected system. Be prepared to reset access credentials if instructed by the Security Team.

STEP 06

Await Further Instructions

Do not reconnect the system until cleared by authorized personnel.

END STATE

The affected system is successfully isolated, reported, and secured, preventing further spread of the attack and allowing the Network Security Team to begin formal incident response procedures.

SUBJECT: Suspected Network Compromise — Response Strategy Evaluation

DATE: [REDACTED] | CLASSIFICATION: RESTRICTED

Introduction

This report addresses how the fleet should respond to a suspected network compromise. As fleet operations increasingly rely on computer networks, the risk of a system-wide breach presents a threat to both operational stability and survival. In an environment where Cylons have gained advanced technological capabilities, even a small vulnerability could lead to catastrophic consequences. The purpose of this report is to evaluate possible response strategies in the event of a suspected compromise and to recommend a plan that balances security with operational functionality. Considering the slim margin of error, it is essential that the fleet adopt a structured and disciplined approach to network threats.

Strategy Evaluation

The fleet has three primary strategies available when responding to network attacks. Each presents distinct trade-offs between security, capability, and operational risk.

⛔

Full System Shutdown

Maximum security, but severely limits the fleet's ability to function. Navigation, communications, and life support systems may be compromised.

NOT RECOMMENDED
⚠

Continued Operation with Monitoring

Maintains full capability but introduces significant risk if the threat spreads unchecked through an active system.

USE WITH CAUTION
✓

Isolation of Affected Systems

Disconnects affected systems while maintaining unaffected systems. Provides the most balanced approach between security and operational functionality.

RECOMMENDED

Summary & Recommendation

This report recommends adopting an isolation strategy as the standard response protocol. This approach aligns with established security procedures while preserving critical operational functions. Isolation allows the Network Security Team to investigate, contain, and resolve threats without rendering the fleet inoperable during a crisis. This approach must be paired with clear reporting chains and pre-established escalation criteria to ensure rapid response.

08

BEST PRACTICES & PREVENTION

Prevention is the most effective form of network security. The following practices must be observed by all personnel at all times to minimize the risk of compromise.

🔑

Credential Management

  • Never share login credentials under any circumstance
  • Change passwords at regular intervals as directed by the Security Team
  • Use unique credentials for each system you access
  • Report lost or suspected compromised credentials immediately
🖧

Network Hygiene

  • Never connect unauthorized devices to fleet networks
  • Ensure all systems are running approved and updated software
  • Disable unused ports and services on all managed systems
  • Confirm network segmentation is active before any maintenance
📡

Communication Security

  • Only use approved, encrypted communication channels
  • Verify the identity of any person requesting system access
  • Do not transmit sensitive data over unverified channels
  • Report any requests that seem to bypass standard protocol
📋

Routine Monitoring

  • Review system logs at the start and end of every shift
  • Document and report any anomalies immediately
  • Participate in scheduled security drills and protocol reviews
  • Escalate unresolved anomalies to the Security Team
🛡

Physical Security

  • Never leave a workstation logged in and unattended
  • Ensure access to server rooms and terminals requires clearance
  • Report unauthorized personnel in restricted areas
  • Lock terminals when stepping away, even briefly
🧠

Situational Awareness

  • Stay informed of current threat advisories from the Security Team
  • Trust instincts — report anything that seems unusual or out of place
  • Do not assume a threat is handled until formally cleared
  • Maintain awareness of who has access to systems around you
